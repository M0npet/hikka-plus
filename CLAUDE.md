# Hikka Plus — правила для Claude

Розширення для hikka.io (WXT 0.21 + React 19 + TypeScript, MV3 для Chrome, MV2 для Firefox).
У збірці замість React — **Preact** (`preact/compat` через alias у `wxt.config.ts`, 0.5.17): код пишемо як під React (типи `@types/react`), але лише API, які є в compat (хуки, `createRoot`, `useId`, `useSyncExternalStore`); content script 429 → 224 КБ. Перевірено попиксельно проти React-збірки (блок плеєра, «Ширше», читалка, вікно налаштувань).
Карта проєкту й рішення MK — у claude.ai-проєкті «Hikka The Project» (`claude/project-map.md`,
`claude/research-readers-and-layout.md`).

## Рішення MK (не порушувати)
- Усе вбудовано в сайт і в його стилі; блок розділів і кнопка — на сторінці тайтлу, читалка — оверлей.
- Джерела — **тільки українські**: Zenko, manga.in.ua, baka.in.ua, Honey Manga, UAManga, DGManga, Animesvit, Смаколики, Runi, NovelHub (novel.org.ua; роботи 18+ сайт віддає лише після входу — не показуємо), FanVers (fan-vers.com, лише переклади), Wattpad (лише історії українською, language 46; платні — ні). Захист читалки (токени, nonce, Referer) не обходимо — такі сайти лише посиланням: `src/sources/links.ts` (Mangra — точно за `hikkaSlug`, FAUST і Mangarama — публічний пошук, Dengeki — посилання на пошук; спершу завжди посилання з блоку «Читати» на Hikka), UI — `src/features/external-links.tsx`. Повний список сайтів і чому деякі не підключені — `claude/sources-ua.md` у claude.ai-проєкті. Senkuro — лише зразок UX.
- Без власного сервера. Віддалено можна оновлювати лише дані (JSON), не код (політики AMO/CWS).
- Не заважати Hikka Features і Hikka Forge: тільки свій Shadow DOM з тегами `hikka-plus-*`,
  класи `hp-*`, чужий DOM не змінювати, клавіші перехоплювати лише при відкритій читалці.
- «Свої тайтли в каталозі» — відкладено, не робити.
- Назва: Hikka Plus, неофіційне; не видавати себе за Hikka.

## Структура
- `entrypoints/background.ts` — fetch за allowlist (`src/core/hosts.ts`), CORS обходимо тут.
- `entrypoints/content/` — монтування блоків (`src/core/mount.ts`, self-healing для SPA), стилі `style.css`.
  Зміну сторінки в SPA перевіряти за `location.pathname` ідемпотентно: подія `wxt:locationchange` (Navigation API) приходить ДО оновлення адреси.
- `src/features/title-state.ts` — спільний стан тайтлу (кнопка, блок, читалка).
- `src/sources/` — джерела (`ReadSource`), автопідбір (`match.ts`, `autoMatchBy` — спільний для нових джерел; підсумок завжди через `settleMatch`: кандидат 0.45–0.8 → підказка «Схоже» в блоці, прив'язка лише по кліку, «Ні» — `Binding.nearNo`).
- `src/core/hikka-auth.ts` + `hikka-api.ts` (лише background) — OAuth Hikka і PUT /read; `src/features/hikka-sync.ts`, `hikka-bar.tsx` — синхронізація лічильника (`setHikkaChapters` — лише вгору; ручне зняття «прочитано» → `lowerHikkaChapters` до останнього розділу, прочитаного поспіль; скидання в «Дані» Hikka не чіпає).
- `entrypoints/hikka-bridge.ts` — скрипт у контексті сторінки (`injectScript`, web_accessible лише для hikka.io): після нашого PUT /read подія `hikka-plus:read-changed` (`src/core/bridge.ts`) → `invalidateQueries` у QueryClient самої Hikka (знаходимо через дерево React) для запитів з `read` в `_id` — віджет «у списку» оновлюється без F5. Зворотно: міст підписаний на кеш запитів Hikka — успішне оновлення `readGet`/`watchGet` (напр. «+/−» у віджеті Hikka) → подія `hikka-plus:hikka-list-changed` → `loadRemoteRead(..., quiet)` у `title-state.ts` → hikka-bar відмічає 1–N. Лічильники з віджета Hikka без нашого входу: `watchGet` → `WATCH_COUNT_EVENT` (сітка серій), `readGet` → `READ_COUNT_EVENT` (`hikka-bar.tsx` відмічає 1–N). DOM Hikka не змінюємо.
- Вікно налаштувань: `entrypoints/popup` (по іконці) і `entrypoints/options` (вкладка) → `src/settings/` (`app.tsx` — розділи Джерела / Hikka / Читалка / Плеєр / Дані; унизу — версія, розробник M0npet і посилання на GitHub, `data.ts` — копія JSON і скидання без токена Hikka, `mount.tsx` — той самий `style.css` у Shadow DOM + тема й кольори Hikka користувача з `src/core/site-theme.ts`, до першого заходу на hikka.io — системна тема). Поля читалки — спільні `NovelFields`/`MangaFields` з `reader/settings-panel.tsx`.
- Читалку можна вимкнути (`ReaderSettings.enabled`, «Показувати читалку» у вікні налаштувань): content script тоді не монтує кнопку й блок і не вантажить тайтл.
- `src/core/source-prefs.ts` — увімкнені джерела й порядок (`local:hp:sources` + `sync:hp:sources`); `sourcesFor`/`linkSourcesFor` їх враховують, content script перезавантажує блок тайтлу при зміні. `src/core/sync-flag.ts` — вимикач синхронізації між пристроями (`local:hp:syncOn`), перевіряється в усіх pull/push.
- `src/core/progress-sync.ts` — прогрес між пристроями через storage.sync (стисло, новіший перемагає).
- `src/core/prefs-sync.ts` — вибір користувача між пристроями: прив'язки (`sync:hp:b:*` — активне джерело, ручні прив'язки, команди; автопідбір НЕ синхронізується, до 80 тайтлів) і налаштування читалки (`sync:hp:settings`). Поле `Binding.u` — час останнього вибору.
- Збірка з клієнтом Hikka: `WXT_HIKKA_CLIENT_REFERENCE`/`WXT_HIKKA_CLIENT_SECRET` (`.env.local`, у CI — секрети репо `HIKKA_CLIENT_*`).
- `src/core/store.ts` — налаштування, прив'язки (`hp:bind2:*`, по кожному джерелу + команди), прогрес
  (`hp:progress2:*`, ключ — номер розділу, щоб не губився при зміні джерела/команди).
- `src/features/reader-url.ts` — відкритий розділ у `#read=джерело:id` (Hikka — SPA на TanStack Router, pushState безпечний).
- Плеєр аніме — `src/watch/` (блок «Перегляд» на /anime/<slug> після `#content-description`; «Ширше» — `wide-layout.ts`: наш host `hikka-plus-watch` НЕ переїжджає в DOM (iframe не перезавантажується) — стає position:absolute на ширину сітки під верхніми картками бічних колонок; місце тримають наші відступи `hikka-plus-gap` у бічних колонках і в центрі; перехід — FLIP-анімація (тривалість — повзунок «Анімація «Ширше»», `WatchPrefs.wideAnim`, 0 = вимк.; `prefers-reduced-motion` свідомо не враховуємо — MK 16:45); Moon завжди «Ширше» (у вузькому блоці блимає — баг Moon); «Ширше» запам'ятовується між тайтлами (`WatchPrefs.wide`); кнопка «На весь екран» — `requestFullscreen` рамки, iframe не перезавантажується): `providers.ts` (Mikai + AnimeON за id з посилань «Перегляд» Hikka, злиття команд), `adapters.ts` (позиція Ashdi/Moon/Fenix через їхній postMessage — m3u8 не витягуємо; iframe лише з `FRAME_HOSTS`; єдиний наш скрипт у фреймах — `entrypoints/player-frame.content.ts` (Ashdi, Moon, Fenix): лише в нашому iframe (`name="hikka-plus"`) і лише за запитом hikka.io (`AMBIENT_REQ` `{on, scan}` / `{seek}`) читає зменшений кадр відео 32×18 і шле його (`AMBIENT_MSG`) на hikka.io — підсвітка навколо плеєра (canvas `.hp-watch__glow`, вимикач «Підсвітка», `WatchPrefs.ambient`); відео без CORS → `{off}`; сам плеєр не чіпає. Підгонку висоти рамки під панель Moon прибрано (0.5.6) — розгойдувала розкладку Moon. Обхід стилю Hikka Features прибрано — вони виправили в 3.1.22), `threshold.ts` (серія зараховується з початку ED з міток, інакше за 90 с до кінця), `skip-marks.ts` + `fp-hash.ts` (мітки OP/ED: плеєр → знайдені самі → AniSkip; скрипт у фреймі за `{scan}` шле відбитки кадру 32 біти двічі на секунду відео `{fp}`, `learnEpisode` порівнює серії тайтлу (спільний шматок ≥ 30 с: OP — у перших 40 % обох серій, ED — в останніх 30 %), зразки OP/ED тайтлу впізнаються в новій серії за ~4 с (`liveFind`); сховище `local:hp:fp:<slug>` — 3 серії, 30 тайтлів; `MarksBar` під плеєром, кнопка «Пропустити» поверх плеєра, `WatchPrefs.marks/skipOp/skipEd`; перемотка — `{seek}` у скрипт фрейму → `video.currentTime`), `lights-off.ts` («Вимкнути світло»: `<hikka-plus-dim>` у body, 4 темні смуги навколо `.hp-watch__view`), `hikka-watch.ts` (PUT /watch лише вгору; дозволи watchlist — окремий вхід `startHikkaLogin(true)`, помилка прав → `error:'scope'`, токен не скидаємо), `watch-store.ts`, `watch-root.tsx`, `watch-block.tsx`. Tortuga — прибрано; Dawn — лише посилання на Mikai.
- Підсвітка пристроїв від відео (експериментально, вимикач «Підсвітка пристроїв» у вкладці «Плеєр», `WatchPrefs.devices`, за замовчуванням вимк.) — `src/lights/`: `PlayerFrame` шле той самий кадр 32×18 у background (`hp-lights`, ≤10/с, `stop` при знятті/`{off}`) → `engine.ts` (запуск увімкнених пристроїв, у кожного свій `minGap`; 3 с без кадрів або зміна `local:hp:lights` — повернути пристрої у свій режим) → `devices.ts`: Philips TV (JointSpace API 6: Android — https :1926, pairing PIN + digest, підпис і ключ як у haphilipsjs; старі — http :1925; `ambilight/mode` manual↔internal, `ambilight/cached` за `ambilight/topology`), WLED (`/json/state` `seg.i`, стрічка від лівого нижнього кута за годинниковою), Hue (REST v1, середній колір на всі кольорові лампи, стан відновлюємо), Razer Chroma (REST SDK localhost:54235 / chromasdk.io:54236, heartbeat, `CHROMA_STATIC`). `digest.ts` — fetch з тайм-аутом, MD5, Digest. Хости пристроїв — optional permissions (`http://*/*`, `https://*/*`), дозвіл на конкретний хост — кнопкою «Підключити» (`settings.tsx`; у popup лише кнопка «у вкладці» — Firefox закриває popup на запит дозволу). Кадр іде лише на пристрої в мережі користувача.
- CI (`.github/workflows/build.yml`): на тегу — реліз; якщо є секрети `AMO_API_KEY`/`AMO_API_SECRET` — `web-ext sign` з каналом зі `store/amo/channel` (unlisted / listed / web) + `.xpi` у реліз. Архів вихідників без `.env*` і `CLAUDE.md` (`zip.excludeSources`).
- Приватність (0.5.18): `PRIVACY.md` (укр. + англ.) — посилання у футері вікна налаштувань; змінюючи, які дані куди йдуть, — оновити `PRIVACY.md` і `data_collection_permissions` у `wxt.config.ts` (Firefox: required `browsingActivity`, `authenticationInfo`, `websiteActivity`; optional `websiteContent` — підсвітка пристроїв, просимо разом із дозволом на хост через `lightsPerms`, без згоди `engine.ts` кадр не шле; `strict_min_version` 140 / Android 142). Запити до сайтів з background — завжди `credentials: 'omit'`.
- Магазини: `store/amo/` — тексти сторінки AMO (`listing.md`), нотатки рецензенту (`reviewer-notes.md`, CI кладе їх у `approval_notes` для listed), канал підпису в CI (`channel`: unlisted | listed | web). Змінюючи дозволи чи потоки даних — оновити `reviewer-notes.md`. `npm run build-for-amo` — збірка, якою AMO перевіряє вихідники.
- Картинки з manga.in.ua мають hotlink-захист — завжди `referrerPolicy="no-referrer"`.

## Перевірка перед комітом
```bash
npm run compile && npm run build && npm run build:firefox
```
Якоря DOM Hikka (`#content-left-side`, `#content-description`, `#content-center`) перевіряти вживу.
Тексти інтерфейсу — українською.
